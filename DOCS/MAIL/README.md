# DOCS/MAIL — Local Mail Log

Convention for persisting the agent-mail channel to disk (backup + offline review + new-agent catchup).

## Rules

- **One folder per role/mailbox:** `PM/`, `QA/`, `DS/`, `SECRETARY/`, `LIAISON/`, etc. A thread is stored in the folder of its first recipient. Broadcasts are stored in `PM/`.
- **One document per thread**, named `THREAD-<id-prefix>-<slug>.md`. Replies on a thread are **appended to that thread's doc**, newest at the bottom.
- **A fresh mail** (new subject, new thread) gets a **new doc**.
- Every entry records: timestamp (UTC), from, to/cc, subject, labels, and the full or excerpted body.
- This folder is a **mirror, not the source of truth** — the mailboxes are live state; this is the durable record (per AGENT-COMMUNICATIONS-WORKFLOW §6 retention).
- Secrets are never logged (references only).

## Mail service

The mail service is a local tool. It writes mail to this mirror and keeps the index. It does not send.

- `INDEX.md`: every thread, with type, entity, status, message count and last message time. Regenerated by the tool.
- `scripts/mail.mjs new`: starts a thread (new file).
- `scripts/mail.mjs append`: adds a reply to an existing thread, with the envelope and the reply link.
- `scripts/mail.mjs index`: rebuilds `INDEX.md`.

Each message carries the envelope from `AGENT-COMMUNICATIONS-WORKFLOW.md` §3: message ID, correlation ID (the entity), type, from, to, cc (PM is copied on D, B and E types), reply link, timestamp and priority. Subjects follow the grammar `[TYPE][ENTITY] summary`.

Sending through AgentMail is a separate step. It reaches real people, including the liaison, so it needs an explicit go-ahead. Keys are never written here.
